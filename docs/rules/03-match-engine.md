# 規則 03：事件驅動比賽引擎

> 實作：`src/systems/match/match_engine.gd`、`series_sim.gd`
> 設計目標：**比賽不是比較兩隊總評。** 紙面較弱的隊伍可以靠 BP、戰術與執行贏球；
> 每一個事件都是由「當下局面」計算出來的，並記錄原因。

## 1. 輸入：TeamContext（賽前快照）

| 欄位 | 用途 |
|---|---|
| 5 名先發（依位置） | 逐項能力參與不同情境的計算 |
| 主教練 | BP 能力、戰術能力、臨場適應力 |
| 戰術方向 `plan` | 影響 BP 權重、初始姿態、打野路線 |
| 侵略性 `aggression` | 影響對線擊殺機率、物件爭奪意願、Gank 意願 |
| 默契 `chemistry`、BP 熟悉度 | 影響執行力與 BP 品質 |
| `orders` | 即時戰術模式（第四階段）的掛鉤：`{分鐘: 姿態}` |

衍生的三個「團隊品質」(0..1)：

- **BP 品質** = 教練 BP 55% + 選手 BP 理解 25% + BP 熟悉度 20%
- **指揮品質** = 最佳指揮者（shotcalling 60%/決策 40%）55% + 全隊決策 25% + 教練戰術 20%
- **執行力** = 默契 35% + 溝通 20% + 團隊合作 20% + 教練戰術 25%

## 2. 每日狀態（Form）

每名選手開賽時抽一次狀態值（約 -0.3..+0.25），乘在他所有表現上：

- 標準差 = `form_sd × (1.5 − 穩定性/100)` → 穩定性低的選手大起大落
- 自信、士氣加成；疲勞扣分
- 壓力扣分 × 比賽重要性（季後賽 1.3、決賽 1.6）× (1.2 − 抗壓性/100)

## 3. 個人表現函式

`perf(選手, 能力權重)` = 能力加權平均 × (1 + 狀態) × (0.80 + 0.25 × 英雄熟練度) × 後期關鍵表現修正

**英雄熟練度是乘數**：同一名選手拿拿手英雄（熟練度 95）比拿英雄池外的英雄（視為 25）約強 17%。
這讓「禁掉對手的拿手英雄」成為真正的戰術。

不同情境使用不同的能力組合，例如：

| 情境 | 能力組合 |
|---|---|
| 對線 | 對線 50% / 操作 30% / 兵線 20%，× 英雄對線強度、英雄當下強度曲線 |
| 團戰 | 團戰 35% / 站位 25% / 操作 25% / 決策 15%，× 英雄強度曲線 × 經濟係數 |
| 打野決策 | 決策 60% / 地圖意識 40% |
| Gank 成敗 | 打野（地圖意識+決策） vs 目標（地圖意識 70%/站位 30%） |
| 分推單挑 | 操作 60% / 對線 40%，× 英雄分推標籤 |
| 視野 | 視野 70% / 地圖意識 30%，輔助權重最高 |

## 4. 逐分鐘流程

```
每分鐘：
  14/20/26/32…分 → 戰術調整（shotcall）
  更新視野
  ≤14 分：對線 + 打野
  >14 分：中期發育
  物件生成？ → 爭奪決策
  ≥14 分：中期營運（分推 → 抓單 → 主動開團）
  推進壓力 → 建築
```

### 4.1 對線（1–14 分）

- 每條線計算雙方對線戰力 → **優勢值 edge**（-1..1）。
- **線權** = edge 的指數移動平均。線權會影響：打野是否能跟上、物件爭奪、推塔。
- 經濟：`lane_gold_per_min ± lane_edge_gold × edge`。
- **對線擊殺**機率 = `lane_kill_base + lane_kill_edge × |edge| + 侵略性`；由誰擊殺取決於 sigmoid(edge)，所以劣勢方也可能反殺。
- **個人失誤**：每名選手每分鐘有失誤機率（見 §6），失誤後對手可能懲罰拿下擊殺。

### 4.2 打野路線（2–14 分）

打野每分鐘從「Gank 上/中/下、刷野、反野」中選擇。權重：

- Gank：英雄前期強度與抓人標籤 × 我方該路線權（隊友能否跟上） × 目標地圖意識弱點 × 侵略性 × 戰術（前期進攻 ×1.5）
- 刷野：英雄後期強度（後期戰術 ×1.5）
- 反野：中路線權

然後依**打野決策能力**加入雜訊——決策差的打野會更常選錯（例如去 Gank 沒有線權的路）。

結果：
- **雙方打野同一路**：反蹲 → 局部 2v2/3v3 戰鬥，依局部戰力決勝。
- **成功率** = `gank_base_success + gank_skill_weight × (打野理解 − 目標警覺) + 0.15 × 線權 + gank_vision_weight × 視野差`（限制在 5%–85%）。
- 失敗時目標交出閃現（短期對線劣勢），12% 機率被反殺。
- **反野**：若對手打野正在 Gank → 竊取資源；否則依打野戰力與中路線權決定反野成敗。

### 4.3 物件與資源交換

| 物件 | 生成 | 效果 |
|---|---|---|
| 虛空幼蟲 | 6 分 | 上路推進值 |
| 預示者 | 14 分 | 中路推進值 |
| 小龍 | 5 分起，擊殺後 5 分 | 每條 +1.5% 戰力；4 條＝龍魂 +8% |
| 遠古龍 | 龍魂後 | 3 分鐘 +25% 戰力 |
| 巴龍 | 20 分起，擊殺後 6 分 | 3 分鐘 +20% 戰力、強力推進 |

**爭奪決策**（雙方各自判斷）：

```
真實優勢 = ln(我方戰力/敵方戰力) + 0.12×附近線權 + 0.1×視野差 + 0.25×存活人數差
感知優勢 = 真實優勢 + 常態雜訊(標準差 0.30 × (1.1 − 指揮品質))
意願     = 感知優勢 + 姿態偏好 + 侵略性 + 情境（必須阻止龍魂/遠古龍 +0.25；巴龍 −0.15）
```

- 雙方都要 → 物件團戰（勝方拿下；險勝時敗方打野可能**懲戒搶龍**，取決於操作差）。
- 只有一方要 → 另一方**資源交換**：在地圖另一側換取推進/鍍層/野區資源。
- **指揮品質決定雜訊大小**：指揮差的隊伍會錯判局勢，打不該打的龍，或放掉該打的龍。

### 4.4 戰術調整（姿態）

在 14、20、26、32… 分鐘，雙方依局勢選擇姿態：

| 姿態 | 傾向 | 主要影響 |
|---|---|---|
| 主動進攻 press | 經濟領先、陣容前中期強 | 物件與開團意願↑ |
| 拖後期 stall | 經濟落後但陣容後期較強 | 迴避團戰、清線防守、發育 +6%、放棄物件 |
| 物件控制 control | 預設 | 爭奪物件意願↑、視野↑ |
| 分推 split | 陣容有分推手 | 觸發分推事件 |
| 抓單 pick | 抓單陣容 | 抓單機率↑、視野↑ |
| 消耗圍塔 siege | 消耗陣容 | 推進壓力↑ |

效用函式包含：經濟差、陣容後期強度差、陣容原型比例、視野差。
**適應力**（教練適應力 50% + 指揮品質 50%）決定雜訊與「固守原打法」的慣性。
姿態與陣容原型一致時，團戰戰力 +4%。

玩家在即時戰術模式下下達的指令（`orders`）會直接覆蓋 AI 的姿態選擇。

### 4.5 中期營運

- **分推**：分推手在邊路施壓。對手的指揮品質決定回應是否正確：
  - 派出單挑夠強的選手守邊 → 可能抓死分推手
  - 單挑不利 → 在中路以五打四強開
  - 判斷錯誤 → 分推方大量推進
- **抓單**：機率取決於抓單標籤、視野差、姿態；被抓者依「站位 × 地圖意識」的弱點加權抽出。
- **主動開團**：機率隨時間上升，並受雙方姿態與戰力比影響。對手在拖後期時，開團方需要開戰標籤勝過對手的反開標籤才能強迫開團。

### 4.6 團戰

```
1. 開戰前失誤：每人一次失誤判定（後期時「關鍵表現」降低失誤率）
     55% 被抓（直接陣亡）/ 45% 關鍵技能空放（本場團戰戰力 −50%）
2. 開戰：開戰方以 (開戰 + 抓單/2) − (反開 + 保護/2) 判定先手
     成功：對手站位最差的人（後排優先）戰力 −60%
     失敗：開戰方的人被反打
3. 逐回合擊殺（最多 10 回合）：
     P(藍方得分) = 藍^k / (藍^k + 紅^k)，k = fight_decisiveness
     戰力 = Σ 個人團戰表現 × 陣營乘數
     陣營乘數 = 陣容剋制 × 陣容契合 × 執行力 × 物件 buff × 姿態一致
4. 撤退判斷：人數落後的一方，依指揮品質與反開標籤判斷能否撤退止損
```

**陣容原型剋制循環**（`comp_analyzer.gd`）：

```
開戰 ─剋→ 消耗 ─剋→ 保護後排 ─剋→ 開戰
抓單 ─剋→ 分推 ─剋→ 團戰     ─剋→ 抓單
```

每個陣容是六種原型的比例分佈；剋制值 = Σ 我方比例 × 敵方比例 × 剋制矩陣。
陣容缺陷（沒前排、單一傷害、無開戰也無反開、無清線）降低契合度。

### 4.7 建築與終局

- 推進值累積 → 建築倒下。每座建築有「血量」：外塔 1.3、二塔 2.0、高地塔 2.6、兵營 1.6、主堡塔/主堡 1.3；鍍層時間（14 分前）、二塔（20 分前）、高地（24 分前且無巴龍）額外加成。
- 推進來源：線權、圍塔標籤、消耗姿態、巴龍、超級兵；防守方清線能力與拖後期姿態減少推進。
- 團戰大勝把「存活人數差 − 1」轉換為推進值，而不是直接推完——一波團戰不會讓 14 分鐘的比賽結束。
- 摧毀主堡即獲勝；60 分鐘仍未結束則以經濟與塔數判定（極少發生）。

### 4.8 追分機制

- **終結賞金**：擊殺連殺中的選手可得額外賞金（最多 +500）。
- **經濟係數是相對值**，指數 `gold_power_exponent` < 1，經濟優勢的邊際效益遞減。
- **英雄強度曲線**：後期英雄在 26 分後逐漸變強，拖後期的戰術因此成立。

## 5. 系列賽中的戰術適應（`series_sim.gd`）

- 每局結束：敗方對勝方 MVP 使用的英雄提高禁用優先度（`ban_bias`），累計生效。
- 敗方教練以「適應力 × 0.6」的機率放下既定戰術方向，改為依陣容與對手調整（flexible）。
- 敗方選邊（選藍方）。

## 6. 失誤

```
失誤率 = mistake_base × 情境倍率
       × (1.6 − 穩定性/100)
       × (1 + 壓力/120 × 比賽重要性)
       × (1 + 疲勞/150)
       × (1 − 當日狀態)
```

測試 `test_consistency_drives_mistakes`：穩定性 20 的隊伍失誤次數約為穩定性 95 隊伍的 2 倍以上。

## 7. 輸出

```
{winner, winner_club, loser_club, duration, kills, gold, dragons, barons, towers_destroyed,
 stances, events[], players{id: {kills, deaths, assists, gold, mistakes, rating, champion}},
 mvp, draft{bans, picks, log, plan, primary}}
```

每個事件：`{minute, type, text, sides, causes[], actors[], gold_diff}`——可直接驅動文字直播、時間軸與賽後分析。

## 8. 校準目標與目前數值

用 `tools/calibrate.gd` 量測（Bo1，ECL 聯賽隨機對戰）：

| 指標 | 目標 | 目前 |
|---|---|---|
| 平均時長 | 28–34 分 | 29.1 分 |
| 平均擊殺 | 20–30 | 27.8 |
| 小龍 / 巴龍（每局合計） | 3.5–4 / 1–1.5 | 4.6 / 2.2（偏高，待調） |
| 實力差 < 3 的冷門率 | 40–50% | 57%（樣本 75） |
| 實力差 3–6 的冷門率 | 28–38% | 33% |
| 實力差 > 6 的冷門率 | 12–22% | 15% |
| 15 分落後 1.5k 以上的逆轉率 | 18–28% | 23% |

（2026-11-22，`tools/calibrate.gd --games=600`，514 場有效對戰）

行為測試（`tests/test_match_engine.gd`）：

- **相同陣容、只差 BP**：好 BP 的一方勝率 ≥ 62%。
- **弱隊 vs 強隊**：強隊 BP 失誤時，弱隊勝率至少提升 12 個百分點。
- **同種子 = 同結果**。
- **關鍵事件皆有原因**。
- **即時戰術指令會被執行並記錄**。
