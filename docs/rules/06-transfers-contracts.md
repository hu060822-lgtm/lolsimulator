# 規則 06：轉會市場與合約（Phase 1 基本版）

> 實作：`src/systems/transfer/transfer_market.gd`

## 1. 市場價值（不等於轉會費）

```
價值 = 8000 × 1.10^(CA − 40)
     × 年輕溢價（≤21 歲：1 + max(潛力 − CA, 0)/40）
     × 老化折價（≥27 歲：每歲 −12%，最低 25%）
     × 合約年限（0.5 + 0.25 × 剩餘年數）
     × 知名度（0.8 + 知名度/250）
```

## 2. 薪資要求

```
要求 = (18000 + 7000 × 1.075^(CA − 40)) × (0.85 + 知名度/300) × (MONEY 目標 ×1.15)
```

## 3. 要價（賣方）

- 先發選手 × 1.5
- 已要求離隊 × 0.7
- 若有解約金，最多等於解約金

## 4. 流程

```
自由球員：offer_contract → 選手合約效用判斷 → 簽約
有合約者：make_transfer_offer
  → 賣方是玩家？ → 收件匣（等待玩家回覆）
  → 轉會費 ≥ 要價 且 買方現金足夠？
  → 選手合約效用判斷（規則 02 §5）
  → 完成：名單、現金、合約、歷史紀錄
```

拒絕會記錄原因：「薪資不足」「球隊競爭力不足」「出場承諾不夠」「不願意留在這支隊伍」「不想離開家鄉賽區」。

## 5. 合約條款

P1：年薪、起訖年份、出場承諾（starter/rotation/backup/prospect）、簽約金、解約金、勝場獎金。
P2 擴充：出場條件、冠軍/MVP 獎金、續約選項、轉會限制、經紀人。

## 6. 尚未實作（P2）

租借、租借買斷、選手交換、經紀人系統、球探誤差、玩家對收件匣報價的回覆流程 UI。
資料結構已預留（`inbox` 的 `transfer_offer` 訊息）。

## 球探與能力誤差（Phase 2）

- 每支俱樂部保存 `scout_knowledge[player_id]`（0–1）。基礎認識：自家選手 1.0、同聯賽 0.5、其他 0.25；每週同聯賽緩慢上升。
- 顯示區間半寬 = `(1 − 認識度) × 14 + 1`，區間中心帶有依 (俱樂部, 選手, 能力) 雜湊而來的固定偏差，因此球探報告可能「一直看錯」。
- 對戰時雙方各自 +0.12 認識度；轉會中心可花 $15,000 派球探 +0.25。
- AI 俱樂部仍用真實能力決策（未來可改為同樣受誤差影響）。

## 財務約束（Phase 2）

- 每週收入 = `wage_budget / 52 × (0.80 + 聲望/300)`。
- 季末：聲望向 55 回歸 8%；薪資預算 = 舊預算 60% + 目標 40%，目標 = 350k + 聲望×20k + 粉絲×0.2 + 現金×8%，再受聯賽 `format.wage_cap` 限制。
- AI 續約依能力排序，超出預算就放棄（`cannot_afford_renewal`）；補強時會考慮他隊合約剩 1 年以內的先發。
- 休賽季最後一天：每支 AI 俱樂部再做一次「只簽自由球員／提拔新人」的補人（`ClubAI.fill_roster`），避免被挖角後開季缺人。
- 十年模擬參考（seed 預設）：9 支不同俱樂部奪冠，最多 5 冠；轉會約 110 筆/年。
